Посмотреть локально: `npx serve site` и открыть адрес, который он напишет. `serve` понимает адреса без `.html`, как nginx на сервере. Подойдёт и `python3 -m http.server -d site 8080`, но тогда нишевые страницы открываются только с `.html` (`/barbershop.html`), а ссылки между ними ведут в 404. Аналитика на localhost не включается.

## Перед запуском

В начале `site.js`, блок `window.SITE`, один на все страницы:

- `whatsapp` — номер для кнопок, только цифры. Стоит `996707160409`, тот же, что на визитке и в КП;
- `telegram` — имя в Telegram без `@`. Пока не задано, кнопки и ссылки Telegram убираются со страницы;
- `ga` — идентификатор GA4 вида `G-ABC123XYZ` (как получить, ниже);
- `demo` — необязательно: ссылка на бота демо-салона (`https://t.me/...` или `https://wa.me/...`), где человек может записаться сам. Пока пусто, ссылка «Или запишитесь сами в демо-салон» скрыта.

Пока там заглушки, аналитика выключена. Каждая кнопка WhatsApp открывает чат с уже набранным текстом: по нему видно, с какой страницы и кнопки пришёл человек («Интересует тариф «Салон» по цене запуска», «Пишу по поводу бота записи для маникюра» и т. п.).

## Выкладка на VPS

Сайт отдаёт тот же nginx, что и админку, отдельный сервер не нужен.

1. **DNS.** У регистратора домена добавить две A-записи на IP сервера (тот же, что у `admin.zapisbot.online`, сейчас `129.121.148.245`): `@` и `www`. Проверить: `dig +short zapisbot.online` и `dig +short www.zapisbot.online` отдают этот IP. Обновление занимает от минут до нескольких часов.
2. **Код.** На сервере `git pull`, затем `docker compose up -d nginx`: контейнер nginx пересоздастся с новой папкой `/srv/site`. Админка при этом недоступна несколько секунд.
3. **Сертификат.** Челлендж отдаёт уже работающий 80-й порт из `admin.conf` (он сервер по умолчанию), поэтому сайт для этого включать не нужно:
   ```sh
   docker compose run --rm --entrypoint certbot certbot certonly --webroot -w /var/www/certbot -d zapisbot.online -d www.zapisbot.online
   ```
   `--entrypoint certbot` обязателен: в `docker-compose.yml` у сервиса certbot своя точка входа с циклом продления, и без этого флага аргументы `certonly ...` молча игнорируются.
4. **Включить сайт.**
   ```sh
   cp nginx/site.conf.example nginx/site.conf
   docker compose exec nginx nginx -t
   docker compose exec nginx nginx -s reload
   ```
   Если `nginx -t` ругается, не перезагружать, а удалить `nginx/site.conf`: со сломанным конфигом nginx не поднимется, и админка тоже.
5. **Проверить.** `https://zapisbot.online` открывается, `https://www.zapisbot.online` и `http://zapisbot.online` перенаправляют на него, `https://zapisbot.online/privacy` и `/barbershop` открывают свои страницы. С телефона: кнопки WhatsApp и Telegram открывают чат. Коды ответов:
   ```sh
   curl -sI https://zapisbot.online/ | head -1                 # 200
   curl -sI https://zapisbot.online/barbershop.html | grep -i '^location'  # 301 на /barbershop
   curl -sI https://zapisbot.online/index.html | grep -i '^location'       # 301 на /
   curl -sI https://zapisbot.online/net-takoy | head -1        # 404, не 200 и не 301
   ```
   Конфиг с этими редиректами не проверялся на живом nginx (локально его нет), поэтому эти четыре строки обязательны.

Продление сертификата делает тот же сервис certbot, что и для админки.

Обновлять сайт дальше: правка в `site/`, `git pull` на сервере. Перезапуск не нужен, nginx читает файлы с диска.

## Google Analytics 4

Бесплатно. Настройка один раз:

1. [analytics.google.com](https://analytics.google.com) → «Администратор» → «Создать» → «Ресурс». Название `Zapisbot`, часовой пояс Бишкек, валюта KGS.
2. «Потоки данных» → «Веб» → адрес `https://zapisbot.online`. Скопировать «Идентификатор потока данных» (`G-...`) в `SITE.ga` и выложить сайт.
3. Проверить: открыть сайт с телефона, в GA4 «Отчёты» → «В реальном времени» должен появиться посетитель.

Какие события сайт отправляет сам:

| Событие | Когда | Параметры |
|---|---|---|
| `contact_click` | нажали кнопку WhatsApp или Telegram | `channel` (`whatsapp` / `telegram`), `place` (где кнопка: `hero`, `plan_salon`, `final`, `dock` и т. д.) |
| `demo_click` | нажали «запишитесь сами в демо-салон» (только если `demo` задан) | `place` |
| `view_pricing` | долистали до тарифов на главной | — |
| `select_period` | переключили «помесячно / за год» | `period` |
| `faq_open` | открыли вопрос в FAQ | `question` |
| `demo_scene` | переключили сценарий в демо на телефоне | `scene` |

`place` одинаковый на всех страницах (`hero`, `final`, `header`, `footer`), страницу GA4 пишет сам: в отчёте добавить разбивку «Путь к странице».

После того как события появятся (до суток):

- «Администратор» → «События» → у `contact_click` включить «Отметить как ключевое событие». Это главная цифра: сколько человек нажали «написать».
- «Администратор» → «Пользовательские определения» → создать параметры уровня события `channel` и `place`. Без этого в отчётах не видно, какая кнопка работает лучше.

Что смотреть раз в неделю: посетители, источники (Instagram, поиск, прямые ссылки), `contact_click` по `place`. Если люди доходят до цен (`view_pricing`), но не пишут, дело в цене или в тексте тарифов.

## Когда что-то меняется

- **Цены.** Тарифы в `index.html` (блок `#pricing`, атрибуты `data-m` и `data-y`), сравнение в таблице, `lowPrice` / `highPrice` в JSON-LD в `<head>` всех страниц, блок `#fit` и ответы FAQ на нишевых страницах (`grep -n "690\|990\|450\|1 490" site/*.html`), текст на `og.png`, и `COMMERCIAL_OFFER.md`.
- **Цена запуска закончилась** (набрали 10 салонов): у «Салона» убрать плашку и зачёркнутую цену, поставить 990 / 9 900. На нишевых страницах то же самое в блоке `#fit` и в FAQ.
- **Демо-переписка.** На главной три сцены в массиве `SCENES`. Ночная запись и перенос — это разговор с AI-консультантом (`src/aiAgent.js`): клиент пишет обычными словами, бот отвечает свободным текстом, без списков с цифрами. Напоминание и предложение из листа ожидания — фиксированные тексты из `src/scheduler.js` и `src/waitlist.js`, слово в слово. На них клиент отвечает цифрой: в стандартном WhatsApp кнопок нет (`src/menu.js`), а свободный текст в ответ на эти два сообщения бот пока не засчитывает как подтверждение. Изменились тексты бота или ИИ научился новому — поправить `SCENES`, секцию `#ai` и вопрос «Клиенту нужно отвечать цифрами?» в FAQ. На нишевых страницах переписка тоже с AI-консультантом.
- **Панель на главной** (секция `#panel`) — уменьшенная копия экрана «Записи» из `public/admin-dashboard.html` в светлой теме. Поменялся вид админки — поправить разметку и стили `.pnl`.
- **Вопросы FAQ.** Разметку для поисковиков `site.js` собирает из самих вопросов на странице, отдельно её править не нужно.
- **Новая страница.** Чек-лист в конце `../business/SEO.md`; не забыть `sitemap.xml`.
- **Политика конфиденциальности** описывает, какие данные хранит бот и кому их передаёт (в том числе DeepSeek). Новый внешний сервис — новая строка там. Это черновик без юридической проверки.
- **Картинка `og.png`** собрана из HTML и снята headless Chrome в размере 1200×630. Чтобы переделать, проще всего сверстать страницу того же размера и сделать скриншот так же.
