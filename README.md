# Beauty Salon Telegram Bot — Google Apps Script + Google Sheets

Телеграм-бот для записи в салон красоты. Раньше был на Node.js/Telegraf/Postgres,
задеплоенный на Railway; переписан на **Google Apps Script** с **Google Sheets** в роли
БД, чтобы не платить за хостинг — GAS и Sheets в рамках обычных лимитов бесплатны.

## Архитектура

- **`Code.js`** — `doPost(e)`, точка входа вебхука Telegram, роутинг апдейтов.
- **`Telegram.js`** — обёртка над Bot API (`UrlFetchApp`), плюс `buildCtx_()`, который
  собирает Telegraf-подобный `ctx` (`ctx.reply`, `ctx.editMessageText`, `ctx.answerCbQuery`)
  из сырого Update, чтобы остальной код было легко писать.
- **`Session.js`** — состояние пошаговых сценариев (запись, добавление мастера/услуги,
  задание часов) в `PropertiesService`, т.к. GAS — stateless вебхук и не может держать
  сессии в памяти между запросами, как это делал Telegraf.
- **`Db.js`** — доступ к бизнес-данным в Google Sheets (мастера, услуги, записи и т.д.),
  повторяет контракт старого `database.js`.
- **`Utils.js`** — форматирование дат на русском, генерация слотов (без изменений логики).
- **`Start.js` / `MyBookings.js` / `Admin.js`** — обработчики команд/колбэков.
- **`Booking.js` / `AddMaster.js` / `AddService.js` / `SetHours.js`** — пошаговые сценарии.
- **`Reminders.js`** — напоминания за 24ч/1ч, вызывается по таймеру вместо `node-cron`.
- **`Setup.js`** — одноразовые функции для первичной настройки (создание листов,
  конфиг, вебхук, триггер напоминаний).

## Развёртывание с нуля

### 1. Установи и авторизуй `clasp`

```bash
npm install -g @google/clasp
clasp login
```
`clasp login` откроет браузер для OAuth — сделай это под тем Google-аккаунтом, на котором
должны жить таблица и скрипт.

### 2. Создай Apps Script проект + Google Sheet одной командой

```bash
cd tg-bot-for-alb
clasp create --type sheets --title "Beauty Salon Bot" --rootDir ./src
```
Это создаст новый Google Sheet и привязанный к нему Apps Script проект, а также файл
`.clasp.json` (он в `.gitignore`, не коммитится — у каждого разработчика свой).

### 3. Залей код

```bash
clasp push
```

### 4. Настрой один раз через редактор Apps Script

Открой проект (`clasp open`), в выпадающем списке функций сверху выбирай и запускай
по очереди (первый запуск каждой функции попросит выдать права):

1. **`createSheets`** — создаёт листы `Users`, `Masters`, `Services`, `MasterServices`,
   `WorkingHours`, `Appointments`, `Counters` с нужными заголовками и форматами.
2. **`setConfig`** — перед запуском впиши свои значения прямо в код вызова или временно
   замени тело функции аргументами, например:
   ```js
   function run() {
     setConfig('123456:ABC-DEF_botToken', '111111111,222222222', 'Asia/Bishkek');
   }
   ```
   и выполни `run`. Значения берутся так же, как раньше в `.env`:
   `BOT_TOKEN` — токен от @BotFather, `ADMIN_IDS` — телеграм ID админов через запятую,
   `TIMEZONE` — часовой пояс салона.
3. Задеплой Web App: **Deploy → New deployment → тип Web app**, Execute as: **Me**,
   Who has access: **Anyone**. Скопируй URL деплоя.
4. **`setupWebhook('https://script.google.com/macros/s/.../exec')`** — пропиши
   реальный URL из шага 3, выполни. Это вызовет Telegram `setWebhook` с секретным
   токеном в query-параметре (GAS `doPost` не даёт доступа к заголовкам запроса, поэтому
   секрет передаётся через URL, а не через `secret_token` заголовок).
5. **`setTriggers`** — ставит триггер `checkReminders` каждые 5 минут (замена `node-cron`).

### 5. Проверка

- Напиши `/start` своему боту в Telegram — должно прийти приветствие с кнопками.
- Пройди полный цикл записи: услуга → мастер → дата → время → подтверждение.
- Через `/admin` (с айди из `ADMIN_IDS`) проверь панель: расписание на сегодня/завтра,
  добавление мастера/услуги, назначение услуг мастеру, задание рабочих часов, отмену
  записи (клиенту должно прийти уведомление).
- Напоминания: вручную запусти `checkReminders` в редакторе на тестовой записи с близким
  временем, чтобы убедиться, что сообщение уходит и `reminder_24h_sent`/`reminder_1h_sent`
  проставляются в `Appointments` (иначе будет дублироваться).
- Логи ошибок смотри в Apps Script → **Executions**.

## Важные ограничения по сравнению с Postgres-версией

- Каждый запрос к `Db.*` читает весь соответствующий лист в память — нормально для
  одного салона (несколько мастеров, десятки записей в день), но не масштабируется на
  тысячи записей.
- Гонки при бронировании и генерация ID защищены через `LockService` — при очень
  высокой одновременной нагрузке возможны небольшие задержки (ожидание лока до 10 сек).
- Не редактируй руками колонки `id`/счётчики в листе `Counters` — сломает уникальность ID.
- Даты/время в `Appointments`/`WorkingHours` хранятся как текст (`YYYY-MM-DD`, `HH:MM`) —
  колонки принудительно отформатированы как «Обычный текст» в `createSheets()`, чтобы
  Google Sheets не превращал их в объекты Date.
